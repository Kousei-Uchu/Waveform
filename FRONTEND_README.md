# Waveform — SwiftUI frontend

The app itself: a SwiftUI layer over
[`WaveformBackendKit`](BACKEND_README.md), which owns all the actual
matching/downloading/library/playback logic. This README covers the
app targets, the widget extension, and how to build the project.

## What's in it

```
Waveform.xcodeproj          — generated by XcodeGen from project.yml, never committed by hand
├── Waveform/                SwiftUI app: Library, Player, Search & Download, Settings
├── WaveformShared/          types shared between the app and the widget extension
└── WaveformWidgets/         Dynamic Island / Lock Screen Live Activity (iOS-only extension target)
```

Two SwiftUI targets, `Waveform-iOS` and `Waveform-macOS`, share
essentially every view; iOS additionally embeds `WaveformWidgets` for
the Live Activity, which macOS has no equivalent for and deliberately
excludes.

## Playback engine

`WaveformBackendKit` defines playback against a `PlaybackEngine`
protocol and ships no implementation of its own — this app target
supplies a VLCKit-backed one (`VLCPlaybackEngine.swift`), the one file
in the whole app that imports VLCKit/MobileVLCKit directly, so playback
isn't limited to whatever formats `AVPlayer` happens to support.

## Lock screen and Live Activity

Transport controls (play/pause/next/previous/seek) wire into
`MPNowPlayingInfoCenter` and `MPRemoteCommandCenter`. The Dynamic
Island / Lock Screen Live Activity (iOS 16.2+) lives in the real
`WaveformWidgets` app-extension target embedded into `Waveform-iOS`,
and tapping it deep-links back into Now Playing via
`waveform://now-playing`. Artwork reaches the extension through a
shared App Group container, since the widget process can't read the
library on its own — see "Before your first build" below.

## Look and feel

The full-screen Now Playing view tints toward the current track's
artwork color rather than sitting on a flat background. Other screens
lean on the system's newer glass materials where available, with a
plain fallback where they aren't, rather than gating a whole feature on
platform support.

## Building it

```bash
brew install xcodegen
xcodegen generate
pod install       # MobileVLCKit / VLCKit, swift-vibrant
open Waveform.xcworkspace
```

`project.yml` at the repo root is the source of truth for the Xcode
project — it defines the `Waveform-iOS`, `Waveform-macOS`, and
`WaveformWidgets` targets and points them at `WaveformBackendKit` as a
local Swift package dependency. Re-run `xcodegen generate` any time
source files are added, removed, or renamed; it keeps the `.xcodeproj`
in sync with what's on disk so nobody hand-edits file references in
Xcode.

**Before your first build**, three things need a real value instead of
the placeholders in the repo:

1. **Bundle ID prefix** in `project.yml`.
2. **App Group identifier**, for the Live Activity's artwork —
   `WaveformShared/AppGroup.swift` and both `.entitlements` files all
   need to agree on it. Skipping this doesn't break anything; the Live
   Activity still appears, it just falls back to a placeholder
   music-note glyph instead of real artwork.
3. **Code signing** for the `WaveformWidgets` target, same as any other
   target — Xcode will prompt the first time you build for a device.
